# ns8-wazuh implementation plan (Wazuh 5.0.0-rc1)

This module installs a central Wazuh 5 server on a dedicated NS8 node. The node sits outside the clusters it watches. Wazuh agents on NS8 nodes, other Linux hosts and Windows hosts send their logs to it. The server decodes them, raises alerts, keeps everything searchable and sends alerts to the customer.

Before each phase, read the `nethserver-ns8-module` skill and the matching pages of the developer manual (`https://nethserver.github.io/ns8-core/modules/<page>/`).

## 1. Decisions

- Single node: one rootless pod with manager, indexer and dashboard.
- Traefik handles every public certificate: the dashboard route and the agent port 1517 use the same FQDN, like ns8-mail and ns8-ejabberd. The dashboard serves plain HTTP on the pod localhost.
- A small internal CA is used only between the indexer, the manager connector and `securityadmin.sh`. Wazuh requires TLS there.
- Users log in with the NS8 user domain accounts, OpenLDAP (rfc2307) and Samba AD (ad). One group is mapped to the admin role.
- Agents enroll with a token generated by a module action (short TTL, limited uses). Agents read journald.
- All decoded logs are searchable in the dashboard. No rclone, no rsyslog container.
- Customer export: native HTTPS webhook (Notifications and Alerting in the dashboard).
- Backup: the NS8 backup (restic), with an indexer snapshot created in `module-dump-state`.
- Firewall: outbound is open. The module opens inbound 1514, 1515 and 1517 on the Wazuh node. The API port 55000 stays private.
- Versions are tracked by Renovate.
- First deliverable is the server module. Deploying the agent on NS8 nodes is a second deliverable.

## 2. Architecture

```text
 Monitored clusters (isolated)           Dedicated NS8 node for Wazuh
 +-----------------------+        +--------------------------------------+
 | NS8 A: mail, samba,   |        | ns8-wazuh pod (rootless)             |
 | nextcloud, traefik    | 1514   |  manager --decode+rules--> indexer   |
 | journald -> agent     | 1515   |     ^ API 55000 (internal)   ^       |
 +-----------------------+ 1517   |     +--------> dashboard -----+       |
 | Other host + agent    | -----> +-----------------+--------------------+
 +-----------------------+ TLS, public IP           | Traefik (public HTTPS)
                                                    v
 Web admin (NS8 LDAP login)      NS8 admin: module UI (status, settings, token)
 Outputs: HTTPS webhook to the customer, NS8 backup (restic) to the remote repository
```

## 3. What Wazuh 5 requires

Checked against the 5.0.0 documentation and wazuh-docker `v5.0.0-rc1`.

- Images `wazuh/wazuh-{manager,indexer,dashboard}:5.0.0-rc1`. The tags exist on Docker Hub. There is no external SQL database: the indexer (OpenSearch) stores the data and the manager has an internal SQLite.
- Certificates and passwords are needed before the first start. There are no default passwords and the character rules are strict. The `remoted` certificate (agent port 1517) is mandatory and its SAN holds the public FQDN.
- `alerts.json`, `archives.json`, `<syslog_output>`, `logall` and Filebeat no longer exist. The manager writes directly to the indexer.
- Decoded events go to `wazuh-events-v5-<category>-*`, alerts to `wazuh-findings-v5-*`, state to `wazuh-states-*`. Events without a decoder are dropped unless `index_unclassified_events` is true.
- Decoders and rules are YAML assets stored in the indexer and synced from the Wazuh CTI API. The node needs Internet access, or the content manager runs in offline mode. Custom content goes through the Content Manager REST API (Draft, Test, Custom spaces). Default limits: 100 integrations, 200 decoders.
- Active Response was rebuilt: channels and an Alerting monitor in the dashboard, and a `block-ip` executable on the agent. It stays disabled by default here.
- Host: `vm.max_map_count=262144`, 4 to 6 GB of RAM, 50 GB of disk.

## 4. Module design

**Images and Renovate.** `org.nethserver.images` lists the three pinned images. `renovate.json` already extends `NethServer/.github:ns8-automerge`, and its regex manager reads `build-images.sh`. To add: one `wazuh` group so the three images move together, and `automerge: false`. The jump from `rc1` to `5.0.0` will probably be manual.

**Pod and systemd.** `wazuh.service` creates the pod. Three children, `wazuh-indexer`, `wazuh-manager` and `wazuh-dashboard`, use `BindsTo=wazuh.service`. Start order is indexer, manager, dashboard, based on the upstream healthchecks. `80start_services` lists every service in `systemctl --user try-restart`. Reference modules: ns8-mattermost for the pod layout, ns8-nextcloud for LDAP.

**Ports and firewall.**
- Dashboard: `org.nethserver.tcp-ports-demand=1`, published on `127.0.0.1:${TCP_PORT}` in plain HTTP. In the image, set `SERVER_SSL_ENABLED=false` and `SERVER_PORT=5601`. Route with `agent.set_route` and Let's Encrypt. The upstream healthcheck uses HTTPS and must be adapted.
- Agent ports 1514, 1515, 1517: fixed ports, `node:fwadm`, `agent.add_public_service` in `create-module/90firewall`, and `org.nethserver.max-per-node=1` like ns8-mail.
- API 55000 and indexer 9200 stay inside the pod and are never published.
- To test: the real source address of agents seen by the manager. With `slirp4netns` it may be masked, while ns8-mail uses `--network=host`.

**Certificates.** Same pattern as ns8-ejabberd and ns8-mail.
1. `configure-module` asks Traefik for the certificate with `agent.set_certificate`.
2. `get-certificate.service` (oneshot) runs `runagent get-certificate --cert-file --key-file $FQDN`. The manager unit uses `Wants=` and `After=` on it.
3. `events/certificate-changed/50get_certificate` checks `agent.certificate_event_matches`, fetches the new certificate and reloads the service. If the manager cannot reload `remoted.pem`, use `try-restart`.
4. Authorization: `traefik@node:fulladm` (route and certificate).
5. Wazuh wants two files (`remoted.pem` and `remoted-key.pem`), so no concatenation like ejabberd does.

Agents already trust Let's Encrypt through the system store, so the Wazuh CA does not need to be distributed. The `remoted` certificate must have `CA:FALSE`, `serverAuth` and the FQDN in the SAN, the full chain, and mode 0640 readable by the `wazuh-manager` group (uid 101, so `podman unshare chown` in rootless).

**Secrets.** Never use `agent.set_env()`. `create-module/10genpasswords` writes `state/passwords.env` (mode 0600) and the container secret files.

**LDAP.** Use `Ldapproxy().get_domain(...)`, the `accountconsumer` authorization, and react to `user-domain-changed` and `ldap-provider-changed`. The service is reached through `10.0.2.2` from the rootless container, as ns8-nextcloud does, with one branch per schema. Apply the configuration with a targeted `securityadmin.sh` call (`FILE=config.yml TYPE=config`, then `roles_mapping.yml`). Never run it without arguments: it replaces the whole security configuration.

**Backup and restore.** `module-dump-state` creates an OpenSearch snapshot (an `fs` repository in a volume, `path.repo` to verify) and `module-cleanup-state` removes it. `state-include.conf` holds the snapshot, `state/passwords.env`, the internal CA and the manager volumes (`etc` with `client.keys`, `queue` with `global.db` and the keystore, `api_configuration`, `var_multigroups`). Do not back up the raw indexer data volume or the manager `data/` directory (downloaded again). Restore runs `06copyenv`, restores the snapshot, then `50call-configure-module` with all restored variables. `clone-module` gives an empty stack.

**Actions.** `configure-module` (host, LDAP, public address, retention, `index_unclassified_events`), `get-enrollment-token` (TTL, uses) and `get-status`. stdout is reserved for JSON, logs go to stderr.

**UI.** Vue 2 and ns8-ui-lib, three pages: Status, Settings, Agents (token and a command to copy). Logs, alerts and rules stay in the Wazuh dashboard.

## 5. Collection and detection

Agents read journald, never files inside volumes. The starting scope follows the NS8 definition of "security" (syslog facilities 4, 10, 13, 14 and `[AUTH]` lines of api-server).

| Source | State on the test node |
|---|---|
| Dovecot | `imap-login: Login: user=<x>, rip=<ip>` in journald. Enough for hours, country and failures. The IP may be internal behind a proxy. |
| Traefik | Access log in journald. |
| Nextcloud | Logs on stderr, `admin_audit` app installed. No user event seen yet. |
| Samba | Per-share audit, writes only by default. It goes to TimescaleDB through syslog-ng, not to journald. |
| Core (api-server) | Successful logins confirmed in journald. Failures and admin actions to confirm. |
| CrowdSec | Logfmt lines in journald. A simple key=value decoder is enough. |
| OpenLDAP | Not verified. No slapd line seen in journald. A log level that traces binds is needed. |

For Samba, propose a small PR to ns8-samba adding a journald output in the syslog-ng configuration.

Minimal rule set: login outside working hours, login from a country not in the allowed list (GeoIP enrichment of the Engine), burst of file operations per user, repeated failures. Thresholds are fixed and tuned per customer. There is no learning of normal behavior and no native impossible-travel detection.

Modules to watch first: mail, samba, openldap, nextcloud, traefik, crowdsec and the core. Then webtop, roundcubemail, ldapproxy, piler, imapsync, mattermost, ejabberd, nethvoice, nethvoice-proxy, dnsmasq and rustfs. Do not duplicate loki, metrics and netdata.

## 6. Export and monitoring

- Customer export: a Custom Webhook channel and an Alerting monitor, created by the module or documented. The customer endpoint must accept an HTTPS POST. Alerts only by default.
- Logs contain user names and IP addresses. The customer chooses the destination and the retention.
- Agents on monitored nodes: journald, FIM (`/etc`, `/etc/nethserver`), auditd and vulnerabilities, with the configuration pushed by agent group.
- Module health: the NS8 Alertmanager does not accept rules from a module. Version 1 relies on the `get-status` action and the dashboard monitors. A Prometheus target and a PR in ns8-metrics can come later.

## 7. Phases

- [ ] **Phase 0, checks** on a test node: upstream rc1 stack on rootless Podman (uid 101 permissions, `memlock`), Let's Encrypt certificate accepted by `remoted` and by an agent without an embedded CA, list of standard decoders, targeted `securityadmin.sh` with LDAP, `path.repo` for snapshots, GeoIP, dashboard over HTTP behind Traefik, OpenLDAP and core log lines.
- [ ] **Phase 1, pod**: three containers, systemd, passwords, internal certificates, clean start.
- [ ] **Phase 2, web access and certificate**: port, Traefik route, `set_certificate`, `get-certificate.service`, `certificate-changed` event, firewall 1514, 1515 and 1517.
- [ ] **Phase 3, LDAP**: OpenLDAP and Samba AD, admin group, change events.
- [ ] **Phase 4, agents**: `get-enrollment-token`, first enrolled agent, journald received.
- [ ] **Phase 5, detection**: NS8 decoders and rules through the Content Manager API, minimal rule set, Samba retest.
- [ ] **Phase 6, export and health**: webhook, module health alerts.
- [ ] **Phase 7, backup**: dump, restore, clone, agents reconnecting.
- [ ] **Phase 8, UI**: Status, Settings, Agents.
- [ ] **Phase 9, tests and finish**: Robot tests, `renovate.json`, README, `org.nethserver.images`.
- [ ] **Second deliverable**: deploy the agent on an NS8 node (script or small module).

## 8. Open points

- List of standard integrations in the CTI (decoders).
- LDAP and `securityadmin.sh` in practice in the rc1 image. The 5.0 documentation does not cover LDAP.
- Rootless: uid 101 permissions, `memlock`. `vm.max_map_count` is a host setting that a rootless module cannot change.
- Consistency of the indexer snapshot and `path.repo`.
- OpenLDAP log level: no bind is traced in journald today.
- Login failures and admin actions of the core in journald.
- GeoIP enrichment enabled in the default policy.

## 9. End to end check

Install the module on a test node, log in with an OpenLDAP account and with an AD account, enroll an agent, see its logs and an alert, trigger the webhook, back up, destroy, restore, and check that the agent reconnects. Robot tests in `tests/`: install, configure, token, uninstall.
